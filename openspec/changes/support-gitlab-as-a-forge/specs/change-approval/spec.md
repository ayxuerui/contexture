## ADDED Requirements

### Requirement: On GitLab the recording identity is the user the token belongs to
On a GitLab store, `ctxr serve`, `ctxr review list` and `ctxr land` SHALL authenticate with the GitLab token
forge-access defines, and SHALL NOT read the GitHub App variables. `ctxr serve`'s start-time check and
`ctxr land`'s check SHALL compare `recording_login` with the username GitLab reports for that token, and
`ctxr serve` SHALL refuse to start, naming both, when they differ.

#### Scenario: A matching token starts the server
- **WHEN** a GitLab store names recording login `ctx-a-approvals` and the token belongs to `ctx-a-approvals`
- **THEN** `ctxr serve` starts

#### Scenario: A mismatched token stops the server
- **WHEN** a GitLab store names recording login `ctx-a-approvals` and the token belongs to `ctx-agent`
- **THEN** `ctxr serve` exits non-zero before binding, naming both usernames

### Requirement: On GitLab a decision is a merge-request note by the recording identity
On a GitLab store, an accepted decision SHALL be recorded as a note on the merge request, posted with the
server's token, carrying the same sentence and marker a decision carries on any forge, and the comment of a
request for changes. The response SHALL show the recorded state, read back from the forge.

#### Scenario: Approve records a note naming the decider
- **WHEN** decider `a@example.com` approves a session at head `h1` on a GitLab store
- **THEN** the merge request carries a note by the recording login whose body names `a@example.com` and `h1`,
  and whose marker gives `approve`, the full `h1`, the email and a time

#### Scenario: A decision marker in a GitHub comment is still ignored
- **WHEN** a comment by the recording login on a GitHub pull request carries a decision marker
- **THEN** it is not read as a decision

### Requirement: A merge method GitLab cannot honor per request is refused
On a GitLab store whose `change_approval` sets `merge_method: rebase`, `ctxr serve` SHALL refuse to start and
`ctxr land` SHALL exit with the setup/usage code before any forge write, each naming the setting and the
methods a GitLab store accepts (`squash`, `merge`).

#### Scenario: Rebase is refused on GitLab
- **WHEN** a GitLab store sets `merge_method: rebase` and `ctxr land` runs
- **THEN** it exits with the setup/usage code naming `merge_method`, and no merge request is merged

### Requirement: On GitLab only notes by the recording identity count as decisions
Every reader of decisions SHALL take, as a GitLab merge request's decision, the latest note that was posted by
the configured recording login, was not generated by GitLab itself, and carries a well-formed decision marker.
A marker in a note by any other user, and GitLab's own approvals, SHALL NOT be read as decisions.

#### Scenario: A marker from another user is ignored
- **WHEN** a note by `ctx-agent` carries a well-formed approve marker for the current head
- **THEN** `ctxr review list` reports the merge request as awaiting a decision

#### Scenario: A GitLab approval is not a decision
- **WHEN** a member approves the merge request in GitLab's own interface and no decision note exists
- **THEN** `ctxr review list` reports it as awaiting a decision, and `ctxr land` does not merge it

### Requirement: On GitLab an approval is mirrored as the recording identity's approval
On a GitLab store, after an approving decision's note is recorded, the server SHALL approve the merge request
as the recording identity for the approved head. After a request for changes is recorded, it SHALL withdraw
that identity's approval when it holds one. A mirror call the forge refuses SHALL NOT undo or hide the recorded
decision: the response SHALL state that the decision is recorded and that the approval was not mirrored, with
the forge's reason.

#### Scenario: An approval shows in GitLab
- **WHEN** a decider approves a session at head `h1` on a GitLab store
- **THEN** the merge request carries the decision note, and GitLab reports it approved by the recording login

#### Scenario: Requesting changes withdraws the approval
- **WHEN** a merge request approved through the approval page later receives a request for changes
- **THEN** the note is recorded, and GitLab no longer reports the recording login's approval

#### Scenario: A failed mirror leaves the decision standing
- **WHEN** the note is recorded and GitLab refuses the approve call
- **THEN** `ctxr review list` reports the session as `approved`, and the decision response says the approval was
  not mirrored and why
