## Why

Four `ctxr session` subcommands wrap operations `git` and `gh` already provide, and one config key claims an enforcement it never delivered. `src/adapters/forge/github.ts` — the whole "forge adapter" — is a 101-line `execFile` wrapper around four `gh` invocations; there is no second forge and no plan for one. `session submit`'s validation pass is the same store-scope check pass `ctxr doctor` already runs. `session land` re-implements `gh pr view`/`gh pr merge`/`git merge --ff-only` behind a state machine, and its `--reap` path is a single-branch inline duplicate of `session reap`'s loop that skips the guard the real one has. `session abandon` reads no store config at all and matches worktrees with no session guard, so it can force-remove any linked worktree and discard uncommitted work. `session reap`'s own safety checks duplicate refusals `git worktree remove` and `git branch -d` already make on their own — its clean/merged pre-checks buy a friendlier report, not any additional safety, and its only spec requirement is the `workspaces_external` key this change also removes.

Every guarantee credited to these commands is anchored elsewhere: `templates/hooks/pre-commit.sh` runs `doctor --staged` before any commit lands; `templates/hooks/pre-push.sh` refuses a direct push to the default branch regardless of which tool pushed. That is this store's actual write-path guarantee, and it does not depend on `ctxr` owning git sequencing. `session.workspaces_external`'s skill-rendering half does not even work as shipped: the rendered `ctxr-session-lifecycle` skill for an external store both instructs and forbids worktree creation in the same document, because only its reclaiming section is conditional and its Start section is not.

Removing this surface is not free — `test/unit/session-land.test.ts` covers 23 asserted failure modes — but those scenarios run against a mocked forge and a mocked git runner: they assert our own state machine's behavior against synthetic inputs, not anything a user experiences. What genuinely needs to survive is three decisions (re-query on unknown mergeability, read state back after merging, refuse a PR head that doesn't match the requested branch), which move into the `ctxr-land` skill as explicit steps rather than disappearing.

## What Changes

- **BREAKING**: `ctxr session submit`, `ctxr session land`, `ctxr session abandon`, and `ctxr session reap` are removed outright — no deprecation shim. The replacement is plain `git`/`gh`, driven by the rewritten `ctxr-submit`, `ctxr-land`, and `ctxr-session-lifecycle` skills, which keep every gate these commands enforced (store validation before staging, an explicit fire gate before any push or PR, mergeability checks before merging, verify-before-retry, and the default-branch push refusal that was always the pre-push hook's job, not the command's).
- **BREAKING**: the `forge` adapter kind is removed. `src/adapters/forge/` is deleted, `AdapterKind` narrows to `harness-generation`, and the default adapter seed stops registering a GitHub forge adapter.
- **BREAKING**: `session.workspaces_external` is removed, along with the reap refusal and the skill-rendering branch built on it. An operator who needs "worktrees here are externally managed" documented has a home for that fact already: an operator-authored file under the guidance directory, which the store's conventions-inlining mechanism already surfaces in `AGENTS.md`.
- A new migration bumps the schema version, stripping any `kind: forge` adapter declarations and the `session.workspaces_external` key from existing stores' `contexture.yaml`.
- `templates/skills/ctxr-submit.md`, `templates/skills/ctxr-land.md`, and `templates/skills/ctxr-session-lifecycle.md` are rewritten so the store's write path runs entirely on `git`, `gh`, `ctxr doctor`, and `ctxr session list` — no `ctxr` command left performs a destructive git operation.

## Capabilities

### New Capabilities

_None._

### Modified Capabilities

- `write-lifecycle`: removes the requirements that `ctxr session submit`/`land` validate, commit, push, rename a branch, and land a session end-to-end; removes the requirement that external workspace ownership disables worktree reclamation (the mechanism it disabled no longer exists); the CLI-managed-session-worktree requirement's scenario naming `submitted or abandoned` is reworded since `session abandon` no longer exists. The requirements that carry the store's actual write-path guarantee — nothing commits to the default branch directly, and commits are validated before they are accepted — are unchanged.
- `adapters`: removes the requirement that forge adapters read pull-request state and merge, and the no-forge-configured degradation scenario tied to `session submit`. The requirement that every adapter kind shares one discovery mechanism is reworded to reflect a single remaining kind.
- `harness-portability`: the shipped-skills requirement for `ctxr-submit`/`ctxr-land` is rewritten to describe git/gh-driven skills instead of skills ending in a CLI command, and to permit forge commands in the land skill (the "never a forge command" scenario existed to route every merge through one audited CLI path; with no such path, the pull request and merge commit are the audit trail). The external-workspace-ownership rendering requirement is removed with the config key it renders from.

## Impact

- **Commands removed**: `src/commands/session-submit.ts`, `session-land.ts`, `session-abandon.ts`, `session-reap.ts`, their registration in `src/run.ts`, and the error classes exclusive to them (nine submit/land errors, `SessionNotFoundError`, `SessionReapWorkspacesExternalError`).
- **Git helpers removed** (last caller goes with the commands above): `renameCurrentBranch`, `pushBranch`, `isWorkingTreeClean` in `src/core/git/repo.ts`; `mainWorktreePath`, `removeWorktree`, `deleteBranch`, `pruneWorktrees` in `src/core/git/worktree.ts` (`pruneWorktrees` is already unused today). After this change `src/core/git/worktree.ts` only creates and reads worktrees; it performs no destructive git operation.
- **Adapter surface removed**: `src/adapters/forge/` (types and the GitHub `gh` wrapper), the `forge` member of `AdapterKind`, the default GitHub forge registration in `src/config/defaults.ts`.
- **Config schema**: `session.workspaces_external` dropped from `SessionSchema`; a lenient parse accepts and drops both legacy shapes (`kind: forge` adapter declarations, the `workspaces_external` key) so an unmigrated store still loads, per the precedent set by `0004-rename-conventions-path-to-guidance-path`.
- **New migration**: strips both legacy shapes from `contexture.yaml`, bumping `SUPPORTED_SCHEMA_VERSION`.
- **Templates rewritten**: `templates/skills/ctxr-submit.md`, `ctxr-land.md`, `ctxr-session-lifecycle.md` (its reclaiming section now covers both merged-and-clean cleanup and discarding unmerged work, absorbing what `reap` and `abandon` did); `src/core/skills.ts`'s `reclaimingStep` collapses to one unconditional block.
- **Tests**: `test/unit/session-land.test.ts` and `test/unit/forge-adapter.test.ts` deleted; submit/land/abandon/reap cases trimmed from the session-lifecycle and adapters integration tests; the stale-forge-adapter fixture in `test/unit/adapters-registry.test.ts` re-pointed at the remaining adapter kind; `workspaces_external: false` stripped from every unit-test config fixture that carries it; a new migration test added.
- **Not changed**: `ctxr session start`, `ctxr session list`, `ctxr session capture` — each computes something (a collision-free branch name, a config-derived worktree listing, a validated note write) that a skill cannot. `ctxr adapters generate` and the `harness-generation` adapter kind are untouched.
