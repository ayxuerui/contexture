# Proposal

## Why

A second opinion needs a plan and nothing from a store, yet today a person can use it over MCP only as a reader of a store: it runs through the `ctxr` runner tool, which the `read` scope reaches, on a server that exists only for a store. So an operator who wants to offer the review to about twenty people must either give each of them a store to read or not offer it. It is also the one tool that spends money on every call, and it cannot be granted or withheld apart from reading. Since `second-opinion-through-openrouter`, a server can answer all three critics with one key and no signed-in model CLI, so a host with no store can now run the whole review.

## What Changes

- **A `second-opinion` scope.** `mcp.second_opinion` in `contexture.yaml` lists who may run a second opinion through the store's server. The scope reaches only the second-opinion tools. A person on that list and no other signs in, sees those tools and nothing of the store. When a store does not write the key, every reader holds the scope, as today.
- **Four tools of its own.** `second_opinion_preflight`, `second_opinion_critique`, `second_opinion_poll` and `second_opinion_result`, each named for its command and taking that command's options as fields. `critique` takes the plan as `plan` and `poll` takes the question as `prompt`, as text.
- **BREAKING: the `ctxr` runner no longer runs a second opinion.** The four commands leave its allowlist and its `input` field goes with them. A call that still names one is refused with the name of the tool that runs it.
- **A member without `read` learns nothing about the store.** The instructions the server returns at `initialize` carry the store's values only for a member who holds `read`.
- **A second plugin, `second-opinion`.** contexture's marketplace gains a plugin that carries only the `ctxr-second-opinion` skill and one command that opens it. It is generated by `ctxr plugin build` and checked against the render like the `contexture` plugin.
- **A server that offers a second opinion and nothing else.** `ctxr second-opinion serve --config <file>` needs no store. Its file names the address, the identity settings, the members and the lineup. It answers sign-in, `/mcp` with the four tools, and a connect page. It reads no forge credential, no App key and no webhook secret, runs no git, and has no browsing, approval or landing route.
- **The skill names the tools.** `ctxr-second-opinion` says how each step runs through the four tools in place of `ctxr` with `@input`.

Unchanged: the critique itself, the lineup and its routes, confinement, the detached run and its bounded fetch, one run at a time per machine user, and a run belonging to the member who started it.

## Non-goals

- **A separate repository, package or image.** The server is a command of `ctxr` and the plugin is built by `ctxr plugin build`. A split would duplicate sign-in, the run folders, the configuration loader and the release chain for no user who exists today. It becomes a mechanical move if a user with no use for `ctxr` appears.
- **The container.** A program for this server in the runtime image, and a compose service that runs it, belong to contexture-images. This change gives that work a command to run.
- **Turning the second opinion off in a store's own server.** A store host that wants the model keys away from its approval key can run this server beside `ctxr serve` and leave its `serve` without model CLIs or an OpenRouter key. A switch that removes the tools from `ctxr serve` is not needed for that, and can be added when someone asks.
- **Per-member spending limits or usage records.** The scope decides who may run a second opinion. How much each person spends is the OpenRouter key's own limit, as the skill already says.
- **Running several second opinions at once.** One run per machine user stays, since a lineup may still start model CLIs.
- **A longer sign-in.** The 30-day token lifetime is a separate decision about every scope.
- **Reading a plan from a store path or a session.** The tools take the plan as text. A member who holds `read` reads the file with `Read` and passes its text, so no tool that the new scope reaches ever opens a store file.
- **Keeping the runner path for one release.** Two ways to run the same command would let the `read` scope keep reaching what `mcp.second_opinion` withholds. The refusal names the tool, which is enough for a client still following an older skill.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `remote-access`: sign-in and scopes admit the `second_opinion` list; the tool rule admits a text field for a file option; the second opinion's requirements move from the `ctxr` runner to the four tools; the server instructions depend on `read`; the connect page names the plugin a member's scopes call for. New requirements cover the server that offers a second opinion only.
- `harness-portability`: contexture publishes a second plugin carrying only the second-opinion skill, checked against the render; the skill's server steps name the four tools.
- `cli-contract`: `ctxr second-opinion serve` and its configuration file.

## Impact

- **Code:** `src/config/schema.ts` (`mcp.second_opinion`, the standalone file's schema), `src/core/mcp/members.ts` (the scope), `src/core/mcp/tool-map.ts` and `tools/index.ts` (the four tools, the runner's allowlist, the alignment rule), `src/core/mcp/tools/cli.ts` (the second-opinion path moves to its own module), `src/core/mcp/surface.ts` and `oauth.ts` (a surface that needs no store and no approval server), `src/commands/second-opinion.ts` and `src/run.ts` (the `serve` subcommand), `src/core/plugin/` (the second plugin, the connect page).
- **Templates:** `templates/skills/ctxr-second-opinion.md`, `templates/mcp/` (four tool descriptions, the runner's description loses its second-opinion line, server instructions for a member without `read`), the plugin templates.
- **Repository:** `plugins/second-opinion/` and a second entry in `.claude-plugin/marketplace.json`.
- **Configuration:** one optional key, `mcp.second_opinion`, with no shipped default. No `schema_version` change and no migration.
- **Compatibility:** a member whose client follows the previous skill text is refused once by the `ctxr` runner, with the tool to call. A store that never writes `mcp.second_opinion` keeps today's access: every reader may run a second opinion.
- **Release order:** an older `ctxr` refuses a `contexture.yaml` that carries `mcp.second_opinion`, so every host updates before a store writes it.
- **contexture-images:** a follow-up adds a program and a compose service for `ctxr second-opinion serve`.
- **Dependencies:** none added.
